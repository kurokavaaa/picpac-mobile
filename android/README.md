# PicPac — мобильное приложение (прототип, Трек 2)

Android-приложение на Kotlin + Jetpack Compose. Работает **без сервера**: все данные
хранятся на телефоне и сохраняются после перезапуска. Оплата тестовая.

## Как запустить на Windows

1. Установите Android Studio (вариант установки — Standard или Custom).
2. `File → Open` → выберите папку `android` (не корень репозитория).
3. Дождитесь синхронизации Gradle: при первом открытии Studio скачает Gradle 9.8.2,
   плагин Android 9.5.1 и библиотеки Compose. Нужен интернет.
4. Если Studio пишет про SDK Platform 37 — согласитесь установить.

### На телефоне по проводу
1. На телефоне: «Настройки → О телефоне» → 7 раз нажать «Номер сборки» → включится режим разработчика.
2. «Для разработчиков» → включить «Отладка по USB».
3. Подключить кабелем, на телефоне разрешить отладку для этого компьютера.
4. В Android Studio выбрать телефон в списке устройств и нажать ▶ Run.

### В эмуляторе
`Device Manager → Create Virtual Device` → любой Pixel → образ системы → ▶ Run.
Чтобы было что выбрать в галерее эмулятора, перетащите пару фото с компьютера в окно эмулятора.

## Сценарий для проверяющего (3–4 минуты)

1. Старт: котик бегает за хвостом, полоска загрузки → экран приветствия → «Начать».
2. Главная: баннеры листаются, «Быстрый заказ» → **Фотокнига Lite**.
3. Конструктор: выбрать формат, число страниц, «Из галереи» → отметить несколько фото.
   Цена пересчитывается сразу. «В корзину».
4. Корзина: изменить количество, ввести промокод **PICPAC10** (−10%) → «Оформить заказ».
5. Без аккаунта откроется вход → «Регистрация» → «Телефон» → ввести номер,
   пароль от 6 символов, решить пример-капчу → предложит привязать email (можно «Позже»).
6. Оформление: имя, способ доставки, адрес → «Перейти к оплате».
7. Оплата: можно сначала «Проверить отказ банка» (заказ сохранится, деньги «не списаны»),
   потом «Оплатить» → экран «Спасибо за заказ!».
8. «Отследить заказ»: лента этапов. Кнопка «Следующий этап (демо)» двигает статус;
   на «Передан в доставку» появляется трек-номер.
9. Поддержка (с главной или из заказа): быстрые вопросы → «Позвать менеджера» → подключается maryrose.
10. Закрыть приложение и открыть снова — аккаунт, корзина и заказы на месте.
11. Профиль → «Сбросить демо-данные» — чистый старт для следующего проверяющего.

## Что проверяет каждое требование ТЗ

| Требование | Где видно |
|---|---|
| Фото → автомакет → правки → проверка → заказ → статус | Конструктор → корзина → оформление → оплата → лента этапов |
| Сохранение | Всё лежит в `files/picpac_state.json`, переживает перезапуск |
| Обработка сбоя | Отказ банка: понятная ошибка, заказ сохранён, повтор безопасен |
| Без дубликатов | Повторное «Оформить» возвращает тот же заказ; оплаченный заказ не оплачивается второй раз |
| Заказ только после регистрации | Корзина ведёт на вход, если аккаунта нет |
| Производство только после оплаты | До оплаты статус «Ожидает оплаты», этапы печати недоступны |

## Что здесь заглушки

- **Оплата** — тестовая, данные карты не вводятся.
- **Чат** — ответы по ключевым словам; менеджер maryrose отвечает шаблонами.
  Точки подключения ИИ и живого чата: `AppViewModel.sendChat` и `AppViewModel.callManager`.
- **Цены** — с super.picpac.by (11.11.2026). Форматы, у которых на сайте нет цены, помечены
  «ориентировочная».
- **SMS/email** — показывается, куда ушло бы уведомление; реально ничего не отправляется.

## Структура

```
app/src/main/java/by/picpac/studio/
├── MainActivity.kt          — точка входа
├── data/                    — каталог и цены, модели, сохранение, AppViewModel (вся логика)
└── ui/
    ├── App.kt               — нижнее меню и переключение экранов
    ├── Navigation.kt        — список экранов и стек «Назад»
    ├── theme/               — цвета и шрифты из макета, светлая и тёмная тема
    ├── components/          — котик (Canvas), загрузка с полоской, иллюстрации, кнопки
    └── screens/             — экраны
```
